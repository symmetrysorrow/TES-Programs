# Tail parameter screening

## Current conclusion

The completed PoST multivariate traces are a useful first proxy for the
single-pixel tail, but they are not the final single-pixel comparison. The
factor-1 parameter vector is the pre-optimization reference point; the
existing completed multivariate set does not contain a completed factor-1
tail trace, so the ranking must be confirmed with a single-pixel baseline and
one-factor-at-a-time runs.

The first parameters to test in the tail are:

1. `stycast_k`: strongest late-tail correlation in the available 20--40 ms
   and 40--70 ms windows. It controls the thermal path from TES toward the
   absorber/support stack and therefore the late time constant.
2. `pb_cp`: strong tail effect, especially in the low/decay waveform. It
   changes stored Pb heat and is a direct candidate for a slower or faster
   recovery.
3. `membrane_cp`: a secondary but repeatable late-tail signal in this dataset;
   it should be checked after the two thermal-path parameters above.

`pb_k` and `tes_cp` are lower-priority for a first tail-only pass. They remain
important for peak and early decay, so they should not be removed from the
final fit; they are simply not the best first probes for the 40--70 ms tail.

The quantitative output is generated by:

```text
scripts/analysis/analyze_tail_parameter_sensitivity.py
```

It writes `artifacts/analysis/tail_parameter_sensitivity/`. The fit uses
`log(parameter factor)` and reports the correlation separately for 5--20,
20--40, and 40--70 ms. Because the available candidates change several
parameters at once, correlation is a screening ranking, not a causal
derivative.

## Why the previous run took 16 hours

The production single-pixel run was 16.34 hours wall time. Its mesh had about
160k nodes and 525k elements, used one rank and direct MUMPS, and ran 273
transient steps. The decisive cost was the tail: the 79 `1 ms` steps averaged
30.9 nonlinear iterations and reached 71 iterations at the worst step. The
early 0.625 us refinement was not the main bottleneck.

The PoST multivariate runner has a second multiplier: every candidate first
performs several G0 steady trials and then a full pulse. Existing pulse logs
are about 17,500--18,600 seconds each, so three full candidates naturally
approach 16 hours even though the mirrored high/low target is already
deduplicated to one Elmer pulse run.

## New execution path

Use:

```text
python scripts/search/run_staged_post_multivariate_search.py --samples 12 --full-top 3
```

The screen uses 12 candidates, a 2.5 us early post-pulse step followed by 100
us tail steps, a fixed G0 factor near the previously calibrated 0.9006, and
the established pilot nonlinear limits (25 iterations, `3e-7`). Only the top
three candidates are sent to the original full configuration. The full run
therefore remains strict and authoritative; the screen is only a gate.

For the production-v2 single-pixel project, the case-builder now also creates
`case_tes_pulse_singlepixel_prod_v2_tail_screen` alongside the unchanged
`case_tes_pulse_singlepixel_prod_v2_full`. The latter must be used for the
COMSOL comparison and final parameter acceptance.
