# 調査報告: G0 の「100倍」不一致の原因 — ElmerGrid の msh 4.1 変換バグによるメッシュ破損

作成日: 2026-07-12

## 要旨

COMSOL では `G0 = 7.854e-6 W/K` で TES が T0 に収束するのに対し、本リポジトリの
Elmer モデルは `G0 = 7.854e-8 W/K`(×1.0181 の較正係数付き)を要した。この約100倍の
不一致の原因を調査した結果、**パラメータや膜 k(T) 式の問題ではなく、
`ElmerGrid` が gmsh msh 4.1 ファイルのノード座標表を誤読し、変換後の Elmer メッシュが
破損していた**ことが原因と特定した。

- `gmsh/project.msh`(gmsh 側)は完全に正常。キャビティは正しく空いており、
  全ボディの体積が設計値と一致する。
- `ElmerGrid 14 2`(Elmer 26.1-Release)による変換で、39388 ノード中 **6111 ノードの
  座標が別ノードの座標と入れ替わり**、基板系ボディにウエハ全域を貫く巨大四面体が
  多数発生。膜アイランド直下のキャビティ領域が導電性シリコン要素で埋まり、
  設計上存在しないはずの垂直熱経路が生じていた。
- この垂直経路により膜の実効熱コンダクタンスが**約100倍**になり、それを補償する形で
  G0 を 1/100 にする較正が必要になっていた。**物理的に正しいのは COMSOL の
  `G0 = 7.854e-6 W/K`。**
- 対策: gmsh 出力を **msh 2.2 形式**に変更すると ElmerGrid が正しく変換することを
  検証済み(全ボディ体積が設計値と一致、全境界 ID 保持)。

## 1. 発端: 実効熱コンダクタンスの幾何係数が約100倍

熱コンダクタンスを G = C·k(C: 幾何係数、k: 膜熱伝導率)と書くと:

| モデル | C [m] | 備考 |
|---|---:|---|
| 吊り下げ膜(4辺の腕、解析値)= 設計意図 | 3.4e-4 | 8·TES_Au_dx·t/(membrane_dx−TES_Au_dx) |
| COMSOL(G0=7.854e-6 で T0 収束、から逆算) | 3.7e-4 | 解析値と一致 → COMSOL は正常 |
| **Elmer メッシュ(固定 k 実験から実測)** | **3.66e-2** | **設計意図の約108倍** |
| アイランド底面→基板の垂直経路(解析値) | 3.1e-2 | 実測値とほぼ一致 |

実測 C は「アイランドが吊り下げられておらず、底面から基板へ垂直に熱が抜ける」
場合の値と一致する。

## 2. Elmer メッシュ (mesh_shifted_merged) の破損状況

### 2.1 ボディ体積が設計値と大幅に不一致

| ボディ | メッシュ体積/設計体積 |
|---|---:|
| abs, TES, Stycast, SiO2_1, Membrane_Si1 | 1.00(正常)|
| Si_1 | 40.3 |
| SiNx | 50.7 |
| Si_2 | 94.8 |
| SiO2_2 | 110.4 |
| Membrane_SiNx | 2596 |

### 2.2 キャビティが埋まっている

膜アイランド(700×700 µm)直下のキャビティ領域(z ∈ [−170, 170] µm)に:

- Si_2(k=0.37、高伝導)要素 902 個(z=168 µm、アイランド底のすぐ下まで)
- Membrane_SiNx 要素 265 個、SiO2_2 要素 55 個

### 2.3 ウエハ全域を貫く巨大四面体

例(body 107 = Si_2 の最大要素、体積 6.6e-10 m³):

```text
node 31109: (-1451.5,  3958.0,   85.3) um
node   915: (  821.6, -1929.4,  123.1) um
node  8795: (  419.8,  -381.8, -175.0) um
node 27448: ( 1136.7,  3251.3,  104.4) um
```

1個の四面体のノードが y = −1.9 mm から +4.0 mm にまたがっており、こうした要素が
基板ボディに多数重なって存在する。これらが k=0.37 のシリコンとしてウエハ全域を
熱的に直結し、キャビティも実質的に短絡していた。

## 3. gmsh/project.msh は正常

gmsh API で直接検査した結果、msh ファイル自体は正しい:

- 各基板層はキャビティ周囲の4枚のフレーム片で構成され、キャビティは空
  (例: Si_2 は 4 エンティティ、合計 6.128e-9 m³ = 設計値と一致)
- 全 3D エンティティの体積・バウンディングボックスが設計と一致
- 要素数 131,886、ノード番号は 1..39388 で連続(欠番なし)

## 4. 原因: ElmerGrid の msh 4.1 リーダー

同一ノード ID の座標を msh と変換後の Elmer メッシュで直接比較した結果:

- **6111 / 39388 ノードで座標が不一致**(別ノードの座標に入れ替わっている)
- 要素の接続(ノード ID 列)は保持されている
- `-merge 1e-10` の有無に関係なく発生(merge 前から破損)

つまり ElmerGrid(Elmer 26.1-Release 付属)が msh 4.1 のマルチブロック $Nodes
セクションの一部ブロックで「ノードタグ ↔ 座標」の対応を誤って読み込んでいる。

## 5. 対策(検証済み)

gmsh 出力を **msh 2.2 形式**に変更する:

```python
gmsh.option.setNumber("Mesh.MshFileVersion", 2.2)
```

検証結果(既存の project.msh を 2.2 に変換 → ElmerGrid 14 2 → Elmer メッシュ検査):

- 全10ボディの体積が設計値と一致(比 0.98–1.00)
- 全境界 ID(bath 1804、mortar 用 1104/1305/1204/1105/1205/1004 等)が保持される

`generate_project_geometry.py` の `builder.write()` 前に上記オプションを設定する
修正を適用する。

## 6. これまでの較正の位置づけ

2026-07-11 に行った較正(G0=7.854e-8 + 膜 k 式の係数 1.0181、
`docs/current_status_repro_20260711.md` 参照)は、**破損メッシュの過剰な熱伝導を
補償するためのもの**であり、物理的な意味はない。メッシュ修正後は:

- `G0 = 7.854e-6 W/K`(COMSOL と同じ物理値)に戻す
- 膜 k 式の較正係数 1.0181 を撤去する

状態で再検証する。なお 2026-07-11 に修正した MATC 演算子優先順位バグ
(ガード式の括弧)はメッシュとは独立な実バグであり、修正は維持する。

## 8. 修正内容と修正後の結果

### 8.1 適用した修正(いずれも generate_project_geometry.py)

1. **msh 2.2 形式で出力**(ElmerGrid の msh 4.1 座標破損を回避):
   `builder.write()` 直前に `Mesh.MshFileVersion = 2.2` を設定。
2. **膜アイランドと基板スタックの共形化**:
   msh 2.2 化だけではキャビティは空くが、アイランドとフレームが「数点の偶然一致
   ノード」でしか接続されず(点接触)、今度は熱が流れにくすぎた
   (回路連成 190.4 mK / 固定電力 341.2 mK に過熱)。
   `_build_group_boolean_geometry` のモンキーパッチで、abs/TES/Stycast を除く
   基板+アイランドの全ボディを `_fragment_touching_body_components` で相互
   フラグメント。その際 `Geometry.OCCBooleanGlue` を一時的に 0 にする
   (glue モードは完全一致面しか接着できず、部分的に重なる面 — 島側面 vs
   フレーム内面、島底面 vs ウエハ全面 SiO2_1 — のインプリントがスキップされる
   ため)。

修正後のメッシュ検証:

- 全ボディ体積が設計値と一致、キャビティは空
- 島の全界面(側面⇔フレーム、底面⇔SiO2_1、層間)でノード共有率 100%

### 8.2 物理的に正しいパラメータでの収束温度

`G0 = 7.854e-6 W/K`(COMSOL と同じ)、較正係数なし、mesh_shifted_merged:

| ケース | TES 体積平均 | T0 = 168.570 mK との差 |
|---|---:|---:|
| 回路連成 | **167.323 mK** | **−1.25 mK(−0.74%)** |
| 固定電力 I0²R0 | 164.557 mK | −4.01 mK |

「G0 を 100 倍いじらないと合わない」状態は解消した。COMSOL と同じ G0 で
T0 の 0.74% 以内に収束する。

### 8.3 残差 −1.25 mK の原因: メッシュ離散化誤差(解決済み)

固定電力ケースが T0 より約 4 mK 低い件を切り分け実験で追跡した。

実験1 — バイパス切断(SiO2_1 の島直下領域のみ座標依存 k で無効化、
`case_constant_power_fixed_no_bypass.sif`):

- 膜アイランド経路のみ: **169.011 mK**(T0+0.44 mK)
- → 膜 k(T) 式 + G0=7.854e-6 は膜経路単独でほぼ正確に T0 で釣り合う

実験2 — 局所細分化メッシュ(`MEMBRANE_REFINE_H=10e-6` フック、島+SiO2_1
シート周辺を h=10 µm、659k 要素、`mesh_refined_test`)でフルモデルを実行:

- **168.938 mK(T0+0.37 mK)**、定常反復 69 回で収束(反復履歴で
  µK レベルのプラトーを確認、界面共形性も全面共有を確認済み)

| 構成 | メッシュ | 固定電力の収束温度 | T0 との差 |
|---|---|---:|---:|
| フルモデル | 標準(132k 要素) | 164.556 mK | −4.01 mK |
| 膜経路のみ | 標準 | 169.011 mK | +0.44 mK |
| フルモデル | 細分化(659k 要素) | **168.938 mK** | **+0.37 mK** |

結論: **残差は標準メッシュの離散化誤差**。膜リング(幅 100 µm、厚さ 1–16 µm)
周辺の要素サイズ(17–38 µm)が粗く、線形四面体は電力駆動問題で熱経路の
コンダクタンスを系統的に過大評価する(温度低め側の誤差)。十分細かい
メッシュでは Elmer も COMSOL と同様に T0 直近(+0.37 mK)へ収束し、
モデリング差・パラメータ差は存在しない。

注意: COMSOL 側の SiO2_1 は「底面は未接続、熱流は側面経由」とのこと
(ユーザー確認)。Elmer 側もキャビティ上の SiO2_1 底面は真空に面しており、
物理構成は同等。

運用上の含意:

- 標準メッシュのままだと固定電力で −4 mK、回路連成で −1.25 mK の
  メッシュ起因バイアスが乗る。精度が必要な計算では細分化メッシュを使う
  (`MEMBRANE_REFINE_H=10e-6 python generate_project_geometry.py` →
  ElmerGrid)。ただし直接法(Umfpack)ではソルバー時間が約 5 分 → 約 3.3 時間
  に増える。中間の h(12–14 µm)や反復法ソルバーで折衷可能。

### 8.4 注意点

- `mesh_shifted_merged` は再生成された。旧メッシュ(破損版)で得た結果
  (`docs/current_status_repro_20260711.md` の 4 ケース比較、150.015/157.008/
  170.441/180.955 mK、および較正 G0=7.854e-8×1.0181)はすべて破損メッシュ上の
  値であり、物理比較には使えない。
- `mesh_shifted_unmerged` 系ワークフローも同じ msh を使うため、旧 msh 4.1
  時代の生成物は同様に破損している。使う場合は再生成が必要。
