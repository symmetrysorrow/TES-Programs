# Normal `dump2event` CLI to HDF5 v2 end-to-end validation

The ordinary `dump2event.exe` was run with explicit `--physics pb-egs5 --hdf5-version 2`, the PHITS run's own input, and the recovered exact Pb medium-2 table. The raw files were generated by PHITS and ended in NCOL=2. No `--normalize-deposits` option was used. Both calls exited 0.

## R100

Command shape:

```powershell
dump2event.exe <R100 dumpall.dat> <R100 event.h5> --physics pb-egs5 --hdf5-version 2 --physics-config <R100 pb_config.json> --stopping-table <egs5_stopping_power_coefficients.csv>
```

- 100 histories; 38,345 records; terminal NCOL=2.
- HDF5: 100 events, 849 particles, 38,245 tracks, 38,077 deposits, 0 unresolved, 0 negative.
- CLI elapsed 3.65 s; HDF5 11,523,587 bytes.
- Same-run internal tally and per-addition mapping: see `RAW_INTERNAL_ADDITION_MAPPING.md`.

## R1000: new independent seed

The PHITS run itself was launched from a fresh run-local input using the recovered diagnostic executable. It completed with exit code 0 in 76.74 s. The ordinary CLI was then run:

```powershell
dump2event.exe <R1000 dumpall.dat> <R1000 event.h5> --physics pb-egs5 --hdf5-version 2 --physics-config <R1000 pb_config.json> --stopping-table <egs5_stopping_power_coefficients.csv>
```

- PHITS: 1,000 histories; 198,060 records; terminal NCOL=2.
- CLI: exit code 0; elapsed 28.72 s.
- HDF5: 1,000 events, 4,954 particles, 197,060 tracks, 195,185 deposits, 0 unresolved, 0 negative.
- HDF5 output: 58,865,989 bytes.

The HDF5 is a flat-offset v2 file and was reread with the repository's v2 reader; all offsets, event records, and deposit records were enumerated. Provenance explicitly leaves `transport_physics_completeness` and all-absorption status undetermined. This proves the opt-in CLI success path for this validated unit-weight Pb/electron slice; it does not make the physical mode a general production converter.
